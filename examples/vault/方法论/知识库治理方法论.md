# 知识库治理方法论

## 为什么需要治理

知识库不是简单的文件堆砌。没有治理的知识库会面临：

- **信息过载**：内容越来越多，找东西反而更难
- **质量参差**：过期的、错误的、重复的信息混杂
- **无法检索**：结构混乱导致检索系统效果差
- **维护困难**：不知道哪些该更新、哪些该删除

## 治理框架

### 1. 分类体系

建立清晰的记忆类型分类，每种类型有不同的生命周期和可信度：

| 类型 | 说明 | 生命周期 | 可信度 |
|------|------|----------|--------|
| fact | 事实性知识 | 长期 | 高 |
| preference | 个人偏好 | 长期 | 中 |
| experience | 经验总结 | 中长期 | 中 |
| safety | 安全规则 | 长期 | 极高 |
| task_state | 任务状态 | 短期 | 高 |
| navigation | 导航索引 | 长期 | 高 |

### 2. 元数据规范

每条笔记必须包含 frontmatter 元数据：

```yaml
---
memory_type: fact      # 记忆类型
status: active         # 状态：active/archived/deprecated/draft
source: manual         # 来源
confidence: high       # 可信度：high/medium/low
tags: [产品, 功能]     # 标签
created: 2026-01-15    # 创建日期
updated: 2026-03-20    # 更新日期
---
```

### 3. 质量巡检

定期自动化检查知识库健康度：

- **结构检查**：frontmatter 是否完整、字段是否合法
- **内容检查**：是否有空文件、超短文件、重复文件
- **过期检查**：expiry 字段是否过期、长期未更新的文件
- **链接检查**：wikilink 是否有断链
- **一致性检查**：向量库索引与实际文件是否一致

## 最佳实践

### 写入原则
1. 一条笔记一个主题，避免大而全
2. 用自己的话重述，而不是复制粘贴
3. 注明来源和可信度
4. 定期回顾和更新

### 检索优化
1. 标题要清晰描述内容
2. 正文开头先给出结论
3. 使用层级化的小标题
4. 适当使用标签辅助过滤
