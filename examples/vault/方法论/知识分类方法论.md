# 知识分类方法论

## 为什么要设计分类体系

没有分类体系的知识库，本质是一个文件夹堆。东西存得进去、找不出来，
用起来全靠搜索碰运气，而搜索又依赖你已经知道该搜什么。
分类体系的作用是把"找"变成"按图索骥"，同时让检索系统拥有可过滤的结构化元数据。

## 设计原则

### 1. 按用途分，而不是按来源分

按"这是干什么用的"分类，比按"这是从哪来的"分类有用得多。
产品手册、技术方案、会议纪要这种按来源的划分，解决不了"我要找答案"的问题。

### 2. 先粗后细，允许演化

一开始别设计五层结构。先定三到五个一级类目跑起来，
某个类目下的笔记超过 30 篇了再拆分。分类体系是长出来的，不是设计出来的。

### 3. 互斥且穷尽

每条知识应当只属于一个类目，且任何知识都能找到归属。
实在两可的内容，宁可增加一个"其他"类目，也不要让作者随手乱放。

### 4. 类目数量控制在 7±2

一级类目超过 9 个，人脑就记不住了，分类本身会成为负担。

## 推荐的一级类目

- **产品**：对外交付物的客观事实（手册、规格、安全指南）
- **技术**：原理、方案、选型依据
- **方法论**：做事的套路与经验沉淀
- **运营**：流程、FAQ、配置说明
- **项目**：具体事项的状态与决策记录

## 元数据比目录更重要

目录只是分类的一种表达，真正让知识可检索、可治理的是 frontmatter 元数据：

| 字段 | 作用 |
|------|------|
| `memory_type` | 知识类型，决定更新周期与治理策略 |
| `status` | 生命周期状态，用于过滤草稿与归档内容 |
| `date_updated` | 判断新鲜度，过期内容降权或提示更新 |
| `confidence` | 可信度，检索结果可携带可信度标记 |
| `expiry` | 明确失效时间，到期自动进入待复核队列 |

## 落地步骤

1. 抽样 100 篇存量笔记，看它们自然聚成几堆
2. 定一级类目，试分类 20 篇，验证是否互斥穷尽
3. 补 frontmatter，先只补必填字段，不追求一步到位
4. 跑一轮体检，修掉缺失与非法值
5. 用三个月，再回头调整 —— 别指望一次设计到位
