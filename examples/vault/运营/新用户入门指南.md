# 新用户入门指南

## 五分钟跑通

第一次使用建议按这个顺序走一遍，全程不需要改任何代码：

```bash
# 1. 安装
pip install -e ".[dev]"

# 2. 用内置示例库构建索引（无需下载模型）
python quickstart.py

# 3. 启动服务，浏览器打开 /docs 看接口
kb api
```

走完这三步，你已经有一个能用的知识库检索服务了。

## 接入自己的知识库

1. 复制配置模板：`cp config.example.yaml config.yaml`
2. 编辑 `config.yaml`，把 `vault_path` 指向你的 Obsidian Vault（或任意放 Markdown 的目录）
3. 全量构建索引：`kb sync --full`
4. 启动服务：`kb api`

配置文件放在**项目根目录**下才生效。改完没反应时，
检查文件位置对不对、键名有没有拼错（拼错会在启动时打印警告）。

## 常用命令速查

| 命令 | 作用 |
|------|------|
| `kb sync` | 增量同步知识库 |
| `kb sync --full` | 全量重建索引 |
| `kb api` | 启动 HTTP API（默认 127.0.0.1:8300） |
| `kb audit` | 知识库体检：元数据、断链、索引一致性 |
| `kb eval` | 检索效果评估，并自检评测集可达性 |
| `kb stats` | 查看索引规模 |

## 核心概念

- **Vault 是唯一事实源**：向量库只是可随时重建的派生索引，索引坏了重建即可
- **混合检索**：BGE 语义向量 + BM25 关键词，RRF 融合；BGE 不可用时自动降级为 LSA
- **自进化闭环**：收集采纳反馈 → 微调 → 离线门禁 → 灰度 A/B → 晋升或回滚

## 下一步

- 想让 Agent 调用：接入 MCP Server，见 README 的配置片段
- 想提升召回质量：先跑 `kb eval` 建立基线，再考虑加两阶段重排
- 想知道知识库脏在哪：跑 `kb audit`，它会指出缺失的元数据和断链
